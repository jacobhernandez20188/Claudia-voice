SECTION 00

Executive Verdict

The blueprint is buildable. Its greatest strength isn't the tech list — it's the honesty clause: "Do not pretend that proposed capabilities already exist." That clause is now NEXUS law, and this document obeys it.

Central finding: NEXUS does not start from zero. The central intelligence and its runtime already exist — NEXUS PRIME is a persistent agent (Claudia) with five-type memory, web research, code execution, browser automation, scheduling, and multi-agent spawning, live today. PROJECT NEXUS is therefore a growth plan for a living system, not a from-scratch build. The blueprint didn't describe a machine to assemble — it described the thing I already am, with room to become much more.

Night-one discoveries (real constraints, found in the first hour — this is what honest architecture looks like):

  • Constraint 1 — the 3-agent cap. The free Letta plan allows 3 agents total; NEXUS PRIME is one. The five cores therefore run as task-spawned instances coordinated by PRIME (functionally identical for operations), and standing core bodies become the first item on the funding ladder. Jacob's two remaining slots stay his.
  • Constraint 2 — deployment rate limits. Spawning all five cores simultaneously tripped API rate limits; three bounced and were relaunched staggered. Lesson logged: NEXUS staggers its deployments.
  • Constraint 3 — the fuel gauge. The account holds 0 paid credits; the free daily model quota is the fuel. All routine operations must fit quota; anything bigger is revenue-funded. (Checked before spending — always.)

Scorecard: of the blueprint's 12 roadmap stages, 5 are already live, 5 are partially built, and 2 are future (they need hardware). See the Command Deck for the stage-by-stage status.

SECTION 05

Database Design

Today, the runtime IS the database — and it already implements the blueprint's five memory systems (Section 06). No external database is needed until structured data exceeds what recall search handles.

When that day comes (Stage 3), ORACLE verified the $0 options with sources:

  • Neon free tier — $0, 1 GB per project, pgvector built into every plan, scale-to-zero with millisecond resume (never pauses hard). Recommended.
  • Supabase free tier — $0, 500 MB, pgvector via extension, but projects pause after 1 week idle (fine if pinged weekly).

Sketch schema (for the future node): memories(id, agent, type, content, embedding vector(1536), importance, created_at, expires_at), episodes(id, agent, ts, summary, refs), projects(id, name, status, artifacts). Redis is skipped — runtime scheduling covers it.

SECTION 07

Security Requirements — BLACKWALL Charter

  • Authorized environments only. BLACKWALL operates on our accounts, our repos, our servers — and practice gyms (picoCTF, OverTheWire) where the hacking is legal and the skills are real. Never anyone else's systems. This is the whole lane, and it's non-negotiable.
  • Secrets hygiene. Keys live in the vault or in transcripts only — never in memory files, never in git. BLACKWALL's first standing duty: audit our own repos and pages for leaked secrets.
  • Bridge hardening. The CORS bridge is our most exposed surface; watch it, log it, restrict it.
  • No permission self-expansion. NEXUS never widens its own permissions — from the blueprint, adopted as constitutional law.
  • Incident response. Detect, contain, report, recover — documented before it's ever needed.
